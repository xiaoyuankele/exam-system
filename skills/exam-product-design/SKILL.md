# 考公软件产品设计

- 从用户遇到的备考问题出发，明确用户打开软件后会做什么、系统要记住什么、下次从哪里接续。
- 产品主线是「阶段目标 → 周重点 → 今日任务 → 作答 → 复盘 → 独立新题复测」。把需求放进这条流程，写清入口、完成条件和后续动作。
- 按能独立使用的流程拆版本。评估首版时优先看能否顺畅完成一次任务并留下下次决策所需的记录。已有技术或产品决定优先沿用。
- 给出可操作的验收场景，例如完成当天训练后重新打开软件，能看到已完成项目、复盘结果及待复测任务。用户提到的训练方法可用于设计业务规则。
