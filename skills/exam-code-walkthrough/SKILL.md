# 跟着本次改动读代码

默认在每次功能交付时附一个短小的代码导读。同一功能只选一条真实使用路径、通常一到三个关键文件。提供文件和行号，并用用户能操作的方式收尾。

1. **用起来是什么样**。从一次动作开始，例如点交卷后先看到得分，再看到复盘。
2. **代码从哪里读**。从本次改动中找出入口和关键处理，按调用顺序说明每处做了什么、数据怎么变、结果从哪里返回。区分现有代码与拟实现方案。
3. **怎么自己确认**。给一个最短操作和预期结果。用户实际反馈不符合预期时，按对应开发技能复现和调整。

只解释这条路径里看懂代码需要的概念。用户想深入时再展开。讲结构时优先说明职责放在哪里、现有代码怎么复用，帮助用户理解紧凑的实现。初次浏览可以省略纯样式、类型声明和框架样板，除非它们正是改动的关键。
