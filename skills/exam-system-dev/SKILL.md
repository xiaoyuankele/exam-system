# 考公系统开发

从项目规定的入口读取本次涉及的领域技能。项目尚未选定技术栈时，根据本地运行、持久化和部署需求决定，并记录影响后续开发的选择。

1. 先检查现有项目和数据。把需求落到具体备考操作，并写清验证方式。例：支持猜对标签后，复盘能筛出猜对题，并为它们安排独立新题复测。
2. 优先保留题目版本、题源、作答尝试和评阅依据，使历史对比可追溯。修订答案或 AI 解释时保留初次作答及当时的评分口径。区分官方资料、用户记录和 AI 推断。缺失字段在展示和统计时保持未知。
3. 根据功能选取必要的状态与边界。涉及模考时验证收卷前的答案可见性、计时口径和重复提交。涉及统计时验证提示题、重做题和新题的分母。涉及 AI 评阅时验证失败或重试不会丢失原稿或重复计入成绩。
4. 从正常用户入口验证请求涉及的路径。交付说明写清已经验证的行为和待收集的训练证据。产品效果用训练表现或节省的操作时间衡量。
